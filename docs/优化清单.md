## 一、P0 阻塞级问题（必须立即修复）

### P0-1. AI Key 明文存储在 SQLite 数据库
- **位置**：`src-tauri/src/commands/settings.rs:11`、`src-tauri/src/db/repo.rs:109-112`、`src/views/SettingsView.vue:6,71-79`
- **问题**：API Key 通过 `set_setting('ai_api_key', apiKey)` 直接以明文存入 `settings` 表。任何能读取 `%APPDATA%\com.shuati-bao.app\shuati.db` 的程序/用户都能拿到 Key。
- **建议**：使用 `keyring` crate 调用操作系统密钥链（Windows Credential Manager / macOS Keychain / Linux Secret Service）。
- **工作量**：中

### P0-2. Tauri CSP 完全关闭
- **位置**：`src-tauri/tauri.conf.json:21-22`（`"csp": null`）
- **问题**：Content Security Policy 设为 null，webview 可以加载和执行任意来源的脚本/样式/连接。配合 P0-3 的 innerHTML 会变成可执行漏洞。
- **建议**：设置严格 CSP：
  ```json
  "csp": "default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; connect-src 'self' ipc: http://ipc.localhost https://*"
  ```
- **工作量**：小

### P0-3. innerHTML 解析 mammoth 输出存在 XSS 风险
- **位置**：`src/views/ImportView.vue:181-185`
  ```ts
  function htmlToText(html: string): string {
    const div = document.createElement('div')
    div.innerHTML = html            // ← mammoth 输出直接赋给 innerHTML
    return div.textContent || div.innerText || ''
  }
  ```
- **问题**：如果文档内含 `<img onerror=...>` 或 `<script>` 等内容，会被注入到 DOM。
- **建议**：改用 `DOMParser` + `parseFromString(html, 'text/html')` 后取 `textContent`，避免内联事件触发。
- **工作量**：小

### P0-4. fs 权限过宽 + 调试插桩代码留在生产
- **位置**：
  - `src-tauri/capabilities/default.json:10`：`"fs:default"`
  - `src/views/ImportView.vue:87-112`（`dbg()` 函数向 `http://127.0.0.1:8899/logs` 上报）
  - `src-tauri/src/lib.rs:18-30`（自定义 `dbg_log` 写入 `exe` 同目录）
- **问题**：
  1. `fs:default` 允许访问任意用户可读路径
  2. ImportView 的 `dbg()` 调试上报代码每次导入产生几十次 fetch 尝试
  3. `dbg_log` 在安装版（Program Files）下可能无写权限
- **建议**：
  1. 收紧 capabilities，仅允许 dialog 选取文件的读取
  2. 用 `import.meta.env.DEV` 包裹 `dbg()`
  3. 把 `dbg_log` 路径改为 app_data_dir，引入 `tracing` 替换
- **工作量**：中

### P0-5. App.vue 导航缺失，多个核心页面无入口
- **位置**：`src/App.vue:5-8`
- **问题**：路由定义了 7 个页面，但顶部导航只有"题库/设置"2 个。`/wrong/:bankId`、`/favorites/:bankId`、`/stats/:bankId` 只能从 HomeView 的题库卡片进入，无面包屑、无返回按钮。
- **建议**：在练习/错题/收藏/统计页顶部加返回按钮或面包屑；或在 PracticeView 顶部加快速跳转。
- **工作量**：小

### P0-6. 索引缺失：practice_records 按 bank_id 查询无索引
- **位置**：`src-tauri/src/db/schema.rs:50-53`、`src-tauri/src/db/repo.rs:128-133`
- **问题**：`bank_stats` 用 `bank_id` 过滤 `practice_records` 全表扫描。题库用久后会变慢。
- **建议**：
  ```sql
  CREATE INDEX IF NOT EXISTS idx_records_bank ON practice_records(bank_id, is_correct);
  CREATE INDEX IF NOT EXISTS idx_records_bank_time ON practice_records(bank_id, practiced_at);
  ```
- **工作量**：小

## 二、P1 重要问题（近期迭代）

### P1-1. 单一全局 Mutex<Connection> 阻塞所有 DB 调用
- **位置**：`src-tauri/src/db/mod.rs:9`、所有 `commands/*.rs` 中的 `db.0.lock()`
- **问题**：所有命令共享一个 `Mutex<Connection>`，任何 DB 操作都会串行化。一次长查询会阻塞 UI 其他读操作。
- **建议**：拆分为 `RwLock<Connection>` 或引入 `r2d2`/`deadpool-sqlite` 连接池，写排队读并发；或启用 WAL 模式。
- **工作量**：中

### P1-2. `unchecked_transaction` 误用
- **位置**：`src-tauri/src/db/repo.rs:36`、`src-tauri/src/db/repo.rs:63`
- **问题**：`unchecked_transaction` 跳过事务状态检查，顶层调用应使用 `transaction()`。改连接池后会绕过事务保护。
- **建议**：改为 `conn.transaction()?`。
- **工作量**：小

### P1-3. CancelFlag 是全局共享，并发导入互相干扰
- **位置**：`src-tauri/src/commands/import.rs:10`、`src-tauri/src/lib.rs:59`
- **问题**：单一全局 `CancelFlag`，同时发起两个导入会互相影响，且 `flag.0.store(false)` 会清掉上一次未处理的取消信号。
- **建议**：每次导入创建独立的 `CancellationToken`（tokio_util），通过 State 暴露当前活跃 token。
- **工作量**：小

### P1-4. `list_wrong`/`list_favorites` 只返回 ID，前端 O(n²) 查找
- **位置**：`src-tauri/src/commands/practice.rs:11-15`、`src-tauri/src/commands/favorite.rs:11-14`、`src/views/WrongView.vue:28-29`
- **问题**：前端拿到错题 ID 后，再 `listQuestions(bankId)` 全量拉取所有题目，然后 `find(q => q.id === id)` 在内存里查找，1000+ 题时是 O(n²)。
- **建议**：增加 `list_wrong_questions(bank_id, limit, offset)` 直接返回 `Vec<Question>`，分页加载。
- **工作量**：中

### P1-5. `bank_stats` 三次独立 COUNT 查询
- **位置**：`src-tauri/src/db/repo.rs:128-133`
- **建议**：合并为 1 次：
  ```sql
  SELECT
    (SELECT COUNT(*) FROM questions WHERE bank_id=?1) AS total,
    (SELECT COUNT(*) FROM practice_records WHERE bank_id=?1) AS practiced,
    (SELECT COUNT(*) FROM practice_records WHERE bank_id=?1 AND is_correct=1) AS correct;
  ```
- **工作量**：小

### P1-6. ImportView chunk 高达 504KB（占总体积 73%）
- **位置**：`dist/assets/ImportView-mCxkgUt3.js`（504KB）
- **问题**：`mammoth` 库占绝大部分体积，被静态 import 进 ImportView chunk。
- **建议**：改为动态 `import('mammoth')` 仅在用户点击"选择文件"后加载；或把 docx 解析移到 Rust 端（`docx-rs` crate）。
- **工作量**：中

### P1-7. 错题重练、错题本"已掌握"功能未实现
- **位置**：`src/views/WrongView.vue`、`src-tauri/src/db/models.rs:46`
- **问题**：DB schema 设计了 `status='pending'/'mastered'` 区分错题状态，但 `list_wrong` 写死 `status='pending'`，前端没有"标记已掌握"按钮，错题本会无限堆积。
- **建议**：WrongView 加"标记已掌握"按钮，调用新命令 `mark_wrong_mastered(bank_id, question_id)`，区分"待重练/已掌握"两个 tab。
- **工作量**：中

### P1-8. 练习模式单一：只有顺序/随机
- **位置**：`src/views/PracticeView.vue:6-9`
- **问题**：设计文档承诺"顺序/随机/错题重练/模拟考试（限时计分）"4 种模式，实际只实现 2 种。
- **建议**：练习页加"错题重练"模式；模拟考试模式加计时器+限时+交卷评分。
